# ADR-001. 에디터 인터랙션 모델: Notion식 → 티스토리식 고정 툴바 WYSIWYG

- 상태: **채택** (2026-08-18)
- 관련 문서: `docs/00-product-vision.md` §3.4·§7-3, `docs/02-information-architecture.md` §5
- 검증 수단: 동작 프로토타입 (record-system-prototype v1 → v2 피드백)

## 맥락

Phase 1에서 기술 에디터를 "Notion식 WYSIWYG"로 확정했다. 이 결정의 본질은
**"쓰는 자리에서 스타일이 바로 보일 것"** — velog 이탈 원인이었던 좌우 분할
마크다운 레이아웃(쓰는 곳 ≠ 보이는 곳)의 배제였다.

프로토타입 v1에서 두 가지 구현 실수가 사용자 검증으로 드러났다:

1. 기술 에디터를 마크다운 소스 입력 + 하단 미리보기로 구현 → **금지한 velog 방식의 재현**
2. 설교 에디터의 마크다운 단축(`#`)이 변환되지 않고 문자로 남음

피드백: "티스토리는 작성 화면 상단에 서식 탭이 있고, 그걸 선택하면 그 스타일이
적용되는 느낌. 티스토리를 레퍼런스 삼아 달라."

## 결정

전 에디터의 리치 텍스트 영역에 **티스토리식 고정 툴바 WYSIWYG**를 적용한다.

1. **정적 상단 툴바** — 문단 스타일 드롭다운(본문/제목1/제목2/인용/코드 블록) + 굵게/기울임/밑줄 + 목록/인용/구분선. 에디터별로 구성을 차등한다 (설교·찬양은 슬림)
2. **쓰는 자리 즉시 적용** — 스타일 선택 시 커서 위치의 블록이 그 자리에서 변환. 소스/미리보기 분리 없음
3. **양방향 반영** — 커서를 옮기면 툴바가 현재 블록의 스타일을 표시
4. **마크다운 병행** — 단축 입력(`#`, `-`, `>`)은 그 자리에서 즉시 변환, 마크다운 붙여넣기는 커서 위치에 서식으로 삽입 (별도 변환 창 없음)
5. **플로팅 툴바·팝업 금지 유지** — 특히 설교 에디터의 "방해 요소 제로" 원칙

## 불변 조항 (00 문서의 본질은 유지)

- 쓰는 자리에서 스타일이 바로 보인다 (WYSIWYG)
- 좌우 분할·소스/미리보기 분리 금지
- 구현 기반은 Tiptap 계열 검토 (Phase 5)

## 영향

- `docs/00-product-vision.md` §3.4·§7-3: "Notion식 WYSIWYG" 표현을
  "고정 툴바 WYSIWYG (쓰는 자리 즉시 적용, 좌우 분할 금지)"로 갱신할 것
- `docs/02-information-architecture.md` §5.3·§5.5: 갱신 완료 (결정 로그 #14)
- Phase 5 (FE): 툴바를 전 에디터 공통 셸로 설계, 에디터별 구성만 주입

## 기각한 대안

- **Notion식 (블록 핸들 + 슬래시 커맨드)**: 사용자의 실제 레퍼런스가 티스토리이며, 슬래시 커맨드·블록 핸들은 학습 비용 대비 이득 없음. Non-goal #4(에디터 무한 자유도 금지)와도 정합
- **마크다운 소스 + 미리보기**: velog 이탈 원인의 재현. 원천 기각
