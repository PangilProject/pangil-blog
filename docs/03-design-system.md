## 1. 컨셉: 기록 카드

> 1,000편의 글은 이미 하나의 서고다. 글 하나 = 목록 카드 한 장.
> 종이·먹·기록의 물성으로 화면을 짓고, 장식은 인쇄물의 문법(괘선·활자·여백·도장)에서만 가져온다.

- 선정 경위: 후보 11종(A~K) 중 **K(목록 카드)를 뼈대**로, **G(활판 낱장)의 순차 등장 모션**을 공통 모션으로 편입
- 매일 발행 = 도장이 찍히고 카드가 쌓이는 경험 → velog 이주 이유 1번(동기부여 시스템)과 직결
- **포스트잇/카드의 물성**이 관리 화면(대시보드 거슬림 메모지)까지 관통 → UI 애착(생존 조건, 00 §3.2)

### 1.1 금지 문법 (안티 바이브코딩)

다음은 이 시스템에서 쓰지 않는다:
필 버튼(pill), 라운드 뱃지 칩, 그라디언트 배경/버튼, 회색 배경에 떠 있는 카드 그리드,
과도한 border-radius(기본 0, 물리적 은유가 있을 때만 최소), 유리 효과(glassmorphism), **한자 표기 일절**.

## 2. 디자인 토큰

### 2.1 컬러

| 토큰 | 값 | 용도 |
|------|-----|------|
| `--paper` | `#FAF7F0` | 지면(페이지 배경) |
| `--card` | `#FEFDF8` | 카드·에디터 시트 |
| `--ink` | `#2B2823` | 본문 먹색 |
| `--ink-soft` | `#6E6759` | 보조 텍스트 |
| `--faint` | `#9C9486` | 메타·비활성 |
| `--accent-faith` | `#C4553B` | 인주 빨강 — faith 액센트, 카드 상단 괘 |
| `--accent-dev` | `#2F5A8F` | 잉크 블루 — dev 액센트 |
| `--ok` | `#3E7050` | 저장됨·크롤러 정상 |
| `--warn` | `#D8A24A` | 저장 중·동기화 대기 |
| `--line` | `#D9E3EC` | 카드 하늘 괘선 |
| `--edge` | `#E7E0D2` | 보더 |
| `--postit` | `#FBF0B8` | 메모지 |
| `--crawl` | `#FBF6E9` | 크롤링 영역 띠 |
| `--chrome` | `#2B2823` | 관리 헤더(먹) |

**사이트별 오버라이드는 액센트 1축이 원칙**: `--accent`에 faith/dev 값만 주입.
허브는 faith 액센트를 공유하되 카드 2장에서 각자의 액센트 사용. (프리모템 #12: 오버라이드 변수를 늘리지 않는다)

다크모드: `--paper #201D18` / `--card #262219` / `--ink #E8E2D4` / 괘선·보더는 명도만 낮춤 / 액센트는 채도 유지·명도 상향(`#D96B50`, `#5B85BF`). "밤의 서고" 무드.

> **M6 확정.** 초안 값을 그대로 채택했다 — 브라우저로 3면을 훑어 색 자체는 손댈 것이 없었다. 실제로 고친 것은 **값이 아니라 누락**이다. 라이트에만 정의된 토큰이 다크에서 라이트 값을 그대로 물려받아 어두운 지면에 크림색 판이 남았다: QT 질문 시트, 주석 상자, 찬양 가사 판, 그리고 카드 그림자의 첫 레이어(`#e3ddcd` 실선). 셋은 하드코딩이었고 하나는 `.dark` 블록의 누락이었다.
>
> 그래서 팔레트에 두 토큰을 더했다 — `--surface-sheet`(카드 안에 한 겹 더 놓이는 시트: QT 질문 판·찬양 가사 판·에디터 섹션)와 `--edge-strong`(`--edge`보다 한 단 진한 테두리: 점선 주석 상자·천공). `--edge-strong`은 갈라져 있던 두 값(`#dcc9b8`·`#d8d2c2`)을 하나로 합친 것이다. 4~5단위 차이는 눈에 보이지 않고, **토큰이 둘이면 다크에서 둘 다 잊는다.**
>
> 가장 놓치기 쉬운 자리는 찬양이었다. 공개 지면(`PraiseView`)이 **에디터 컴포넌트(`SectionBlock`)를 재사용**하고 있어서 "관리 화면이니 라이트 값이어도 된다"고 지나쳤다. 그래서 색을 고치는 대신 가드 테스트를 세 개 넣었다(`lib/site/darkPalette.test.ts`, `lib/site/publicColors.test.ts`) — 그중 하나는 **공개 지면이 빌려 쓰는 외부 컴포넌트 목록이 실제 import와 일치하는지** 본다. 이 유형은 고장이 아니라 "조금 이상해 보임"으로 나타나서 눈으로만 잡으면 언젠가 놓친다.

### 2.2 타이포그래피

| 역할 | 서체 | 용도 |
|------|------|------|
| 본문 | **Pretendard** | UI 전반, 기술 글 본문, 답변 |
| 세리프 | **Gowun Batang** | 글 제목, 말씀 인용, 요약, 기도문 — "성별된" 자리에만 |
| 타자기 | **Nanum Gothic Coding** | 청구기호, 날짜, 라벨, 메타 — 기록 체계의 목소리 |
| 코드 | **JetBrains Mono** | 코드 블록, 절 번호 |

- 위계는 서체 교체가 아니라 **역할 교체**로 만든다: 메타는 항상 타자기, 신성한 텍스트는 항상 세리프
- 모두 무료(OFL/SIL 계열) — 라이선스 비용 0원 유지
- 본문 폭: 읽기 지면 최대 660~720px, 행간 본문 2.0 / 말씀 2.15

### 2.3 형태·그림자

- radius: 기본 `0`. 예외: 칸막이 탭 상단 `5px 5px 0 0` (물리적 서랍 칸막이 재현)
- 카드 그림자 2단: `0 1px 0 #e3ddcd` (종이 두께) + `0 8px 18px rgba(60,50,35,.10)` (들림)
- hover 시: `translateY(-5px) rotate(0)` + 그림자 강화 — "카드를 집어 든다"

## 3. 시그니처 요소

| 요소 | 정의 | 쓰이는 곳 |
|------|------|----------|
| **기록 카드** | 붉은/파란 상단 괘(1.5px) + 하늘 괘선(27px 간격) + 청구기호 + 하단 천공. 미세 회전(±1도) | 목록, 허브, 대시보드 |
| **청구기호** | `QT-1043` `PR-0388` `SR-0104` / TECH `0072 · 카테고리`. 통산 번호 = 1,000편+ 이력의 시각화 | 카드 좌상단, 상세 메타 |
| **칸막이 탭** | 서랍 칸막이 형태의 필터 탭. 활성 = 액센트 상단 인셋 | F-01/D-01 필터, **F-03 질문 그룹 헤더** (목록↔상세가 같은 언어) |
| **상태 도장** | 기울어진(3도) 스탬프 테두리 배지: "초안 도착"/"새로 시작" | A-01 오늘의 카드 |
| **테이프** | 반투명 마스킹테이프 | 허브 카드, 오늘의 카드 |
| **메모지** | 노란 포스트잇 = "거슬림 목록" (프리모템 #3 습관의 UI화) | A-01 |
| **크롤링 띠** | 미색 배너 "날마다 솟는 샘물에서 가져옴 · 시각 · 질문 6 · 주석 1" — 가져온 것임을 표시하되 전부 편집 가능 | A-04 |
| **천공** | 카드/지면 하단 구멍 — 서고의 흔적 | 카드, 상세 지면 |

## 4. 모션

| 규칙 | 값 |
|------|-----|
| 순차 등장 (G 계승) | 요소당 80~90ms 스태거, `opacity + translateY(12px)` |
| 이징 | `cubic-bezier(.2,.9,.3,1)` 단일 (스프링 느낌은 도장·매듭 등 물리 은유에만 `.34,1.56,.64,1`) |
| 카드 hover | 300ms 들어올림 |
| 저장 인디케이터 | 점 색으로 상태 (회색 대기/호박 저장 중·동기화 대기/녹색 저장됨) |
| 접근성 | `prefers-reduced-motion` 시 스태거·전환 생략, 상태는 즉시 표시 |

원칙: **모션은 물리 은유가 있는 곳에만** (카드가 꽂힌다, 도장이 찍힌다, 지면이 인쇄된다). 장식적 앰비언트 모션 금지.

## 5. 화면별 적용 규칙 (4-2)

### 5.1 목록 (F-01 / D-01)
- 카드 그리드 `minmax(250px, 1fr)`, 미세 회전 ±1도 (hover 시 0도로)
- 상단: 월 표기 + "이번 달 N장 · 통산 N장" (통계 UI 없이 동기 부여 — Backlog 대시보드의 선발대)
- 칸막이 탭 필터 = F-02/카테고리 뷰. 빈 필터 상태 문구: "이 칸은 아직 비어 있어요"

### 5.2 상세 (F-03 / D-02)
- **카드 → 펼쳐진 지면**의 연속성: 상단 괘·청구기호·천공이 그대로 옴
- QT: 말씀 = 붉은 세로 괘 + Gowun Batang / 주석 = 점선 상자 / 질문 그룹 = 칸막이 탭 형태 / 요약 = "오늘의 요약" 헤더 + 세리프
- 설교: 제목·말씀 인용 블록·본문(서식)·요약. 찬양: 임베드 + 섹션 라벨(타자기) + 가사(세리프) + 묵상과 기도
- 기술: 코드 블록(먹 배경), 목차(TOC)는 Phase 5에서 위치 확정 (지면 우측 여백 vs 상단)
- 발행 직후 진입 시 "방금 발행됨" 칩 (녹색)

### 5.3 에디터 (A-04~07) — ADR-001 반영
- 공통 셸: 브레드크럼 + 저장 인디케이터 + 임시저장/발행 버튼 → 그 아래 **고정 툴바** → 에디터 시트
- 툴바 구성 차등: 기술(전체) / 큐티(전체, 답변·요약에 적용) / 설교(슬림: 소제목·말씀 인용·굵게·목록) / 찬양(슬림: 인용·굵게 — 가사 칸은 서식 없음)
- 찬양 가사 칸 무서식은 의도: 타이핑 = 묵상 (01 문서 핵심 원칙)
- 발행 버튼: 확인 모달 없음. 발행 → 공개 페이지 이동
