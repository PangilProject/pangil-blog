## 0. MVP 정의

> **MVP = 티스토리 없이 90일 버틸 수 있는 최소 기능** (00 §4.1 ②)

공식 성공 판정은 "이주 후 90일 시점에 티스토리로 회귀하지 않음"이다. 따라서 MVP는 "블로그가 잘 되는 것"이 아니라 **"루틴이 도구에 녹아드는 것"**을 목표로, 다음을 최소 조건으로 한다:

1. 4타입(QT/설교/찬양/기술) 작성·발행이 매일 루틴 그대로 돌아간다
2. QT 초안 자동 생성(최대 가치, 00 §7-1) + 실패 시 수동 폴백
3. 설교 라이브 작성 **무손실**(프리모템 #2 최상)
4. 완전 이주 — 티스토리 병행 없음(00 §3.5). 기존 글 마이그레이션 완료
5. 공개 페이지가 크롤러에 완성 HTML 제공(SEO), 발행 즉시 반영
6. 통계 **수집** Day 1(대시보드는 나중)
7. 크롤러 사망을 시끄럽게 만드는 방어(프리모템 #1)

우선순위 철학(00 §4.0): **작성 경험 > 지속성 > 독자.** 독자 지표(유입)는 후행이므로 MVP 판정에 넣지 않는다.

## 2. 빌드 마일스톤

> 크기: S / M / L / XL (상대 규모, 달력 추정 아님 — 1인+AI 협업 페이스는 변동 큼). 각 마일스톤은 완료 기준(DoD)을 만족해야 다음으로 넘어간다.
> **선행: 기획 Phase 9(AGENTS.md/CLAUDE.md 확정)** — 빌드 시작 전 협업 규칙 완성. AGENTS.md 빈칸(테스트 전략·폴더 구조·코딩 컨벤션)은 06에서 확정된 fixture+dry-run 규약으로 채운다.

### M0 — 기반 (Foundation) · M
- Next.js App Router + TS(strict) + Tailwind + shadcn/ui 셋업
- Supabase + Prisma, **05 §1.4 스키마 전체 migrate**, categories 시드(회고/FE/BE/…)
- middleware 3호스트 분기 + `?site=` 개발 폴백 (04 §1.3)
- Supabase Auth 단일 관리자 + `withAdmin` 가드 + MFA + RLS deny-by-default (05 §3)
- **DoD**: 로그인→/admin 진입, 세 호스트가 각 자리로 리라이트, 스키마 배포, `npm run build` 통과

### M1 — 디자인 시스템 구현 · L
- 토큰(컬러/타이포/그림자)·폰트 로드·다크모드 초안 (03 §2)
- 핵심 컴포넌트: RecordCard, DividerTabs/GroupTab, ScriptureBlock, AnnotationBox, SectionBlock, SaveIndicator, StateStamp, CrawlBand, EditorToolbar 셸, Tape/PostIt/Punch (03 §6)
- 순차 등장 모션 + `prefers-reduced-motion` (03 §4)
- **DoD**: `record-system-prototype-v2` 수준을 실제 컴포넌트로 재현(확인 페이지). 3면 무드 오버라이드가 `--accent` 1축으로만 동작(프리모템 #12)

### M2 — 에디터 (심장) · XL ⚠ long pole
- 공통 셸 + 고정 툴바 WYSIWYG(ADR-001), Tiptap + RHF Controller (04 §2.1)
- 자동 저장 상태기계: debounce 1s / **maxWait 5s** / 낙관적 / 백오프 (04 §2.2)
- 로컬 보존 2계층 — 전 에디터 보험 미러 + **설교 로컬 우선(로컬=진실)** (04 §2.3, 프리모템 #2)
- 4 에디터: QT(답변6+요약) · 설교(라이브 슬림·방해 제로) · 찬양(섹션 dnd-kit + 기도문) · 기술(마크다운 붙여넣기 변환)
- Zod Draft/Publish 2벌 + `publishPost` 게이트(청구기호 트랜잭션) (05 §2·§3.4)
- 찬양 제목 자동 제안(YouTube oEmbed) (00 §7-4)
- **DoD**: 각 타입 초안→자동 저장→발행 완주. **설교 네트워크 차단 상태에서 무손실 + 복구 배너 동작**. 큐티 답변 공란은 UI 경고만(발행 차단 없음)

### M3 — 렌더링 & 공개 페이지 · L
- `renderRichText` 노드 매퍼 + 타입별 뷰(QtView/SermonView/PraiseView/기술) (04 §3.1)
- Shiki 서버 하이라이팅(먹지 테마) (04 §3.2), 이미지 Supabase Storage + next/image (04 §3.3)
- TOC(데스크탑 우측/모바일 상단) (04 §3.4), OG 카드 `@vercel/og` (04 §3.5)
- SSG + **on-demand revalidate 태그 체계**(`tag:{site}:{name}` 정밀화 반영, 05 §5) (04 §1.2)
- 목록/상세/태그/카테고리 + "이번 달 N장·통산 N장" 헤더(03 §5.1) + RSS(요약+링크)/sitemap Route Handler
- **검색(D-04/F-05)**: `pg_trgm` + `searchText`(발행 시 평문 추출). 작성자 1순위 옛 글 접근 경로 → MVP 편입 (05 §4A)
- **마크다운 export**: 전 글 일괄 `.md` 내보내기(renderRichText 마크다운 타깃 재사용 + 프론트매터). lock-in 방어 (07 §3 참조)
- **다크모드 수동 토글**(next-themes, OS 기본), 클라이언트 아일랜드 4개
- 허브 v1 **정적 한 페이지** + 개인정보처리방침 정적 페이지(H-02) (01 §3.3)
- **DoD**: 발행 즉시 공개 반영, 크롤러가 완성 HTML 수신, OG 카드 생성, RSS(요약)/sitemap 유효, 검색 동작, md export 동작, 아일랜드 4개(복사·TOC·YouTube lite·테마 토글)

### M4 — 크롤러 & 자동화 방어 · M
- Actions 크롤러 + `/api/crawler/ingest` + **watchdog(Vercel 크론)** + 수동 폴백 (06 §1~7)
- fixture 단위 테스트 + `--dry-run`(커밋 조건)
- MVP 편입 자동화: **DB 정기 백업**, **미작성일 리마인드**(watchdog 인프라 재사용) (06 §8)
- **DoD**: 매일 QT 초안 자동 생성, 실패 시 당일 Slack, watchdog가 "미실행" 감지, A-01 폴백 카드 노출, 사용자 편집 초안 보호(`isUserEdited`)

### M5 — 마이그레이션 · L ⚠ 수동 검토 비중 큼
- 파서 4단계(05 §6.1) + 타입별 컨버터 + callNumber/slug **소급 부여**(원본일순) + 이미지 이관
- dry-run 리포트 → 검토 큐 → **전량 PUBLISHED 적재**(결정 (가)) → 전체 rebuild
- publishedAt = 백업 메타 → RSS 크로스체크 폴백 (05 §6.5)
- **DoD**: 티스토리 전량 이관, 청구기호 소급, 원본 작성일 보존, 게이트 실패분 수동 보정 완료, 깨진 이미지 0

### M6 — SEO · 통계 수집 · 출시 하드닝 · M
- 서치콘솔(구글·네이버) 등록 + **검색엔진 자동 제출**(IndexNow — 06 §10 #5에서 채널 확정, sitemap/RSS ping은 존재하지 않는 경로였다) (06 §8, 00 §7-7). 글 OG 카드는 M3에서 완료 — **구조화 데이터(JSON-LD)·canonical·파비콘/매니페스트·지면 OG 카드는 M6에서** 붙였다(M3 DoD가 글 상세만 봤다)
- stat_events beacon + visitorHash + 봇/Origin 필터 + Upstash rate limit (05 §4)
- 다크모드 튜닝, "거슬림 목록" 습관 셋업(프리모템 #3 — A-01 메모지로 구현, 03 §3), 3면 디자인 일관성 최종 점검(--accent 1축을 가드 테스트로 고정)
- **DoD**: 서치콘솔 등록·색인 요청, 통계 수집 검증(내 방문 제외 확인), SEO 투자를 기술 글에 집중(00 §6.3)

**출시 → 이주 → 90일 판정.** 개발 기간 중 티스토리 루틴 유지로 공백 제로(00 §3.5).

## 5. 90일 판정 메커니즘

- **판정선**: 이주 후 90일 시점에 티스토리로 회귀하지 않음 = 성공(00 §4.1, 부록 B-1 "그 기간 지나면 무조건 내 블로그만 쓸 듯")
- **병행 관측 지표**(판정 보조, 조급해하지 않음):
  - 작성 마찰: QT 입력 노동 0분 달성(크롤러 가동) — 존재 이유 지표
  - 지속성: 주간 작성 완주율이 티스토리 수준 유지, 크롤러 월 실패 ≤2회·당일 인지
  - 정성: "묵상에 집중하게 됐다", "UI를 자랑하고 싶다", "개선이 부채가 아니라 재미" (00 §4.2)
- **독자 지표는 후행**: 6개월 일 10~15 / 12개월 20~30(스트레치). 유입 0이어도 스트릭·누적 글 수로 동기 보완(프리모템 #4)

## 6. 크리티컬 패스 · long pole

```
Phase 9(AGENTS.md) → M0 → M1 → M2(XL) → M3 → M4 → M5(검토무거움) → M6 → 출시
                                  └── 심장·최장. 설교 무손실이 최우선 리스크 ──┘
```

- **최장 폴 = M2(에디터).** 특히 설교 로컬 우선 저장은 프리모템 #2(최상)라 여기서 실패하면 전체 신뢰가 무너진다. M2에 시간을 몰아준다.
- **M3 이후 병렬 여지**: M4(크롤러)·M5(마이그레이션)는 M3(렌더링) 완료 후 일부 병렬 가능. 단 M5 검증은 M3 렌더가 있어야 하므로 M3에 종속.
- **완벽주의 억제**(프리모템 #10): 각 마일스톤 DoD를 "완주 가능한 최소"로 잡고, 개선 욕구는 "거슬림 목록"(M6)으로 미룬다.
