# 00. Product Vision — 묵상+기술 통합 블로그

> 상태: **확정 (Phase 1 완료: 1-1 인터뷰 / 1-2 성공 기준·Non-goals / 1-3 대안 분석)**
> 최종 갱신: 2026-08-18
> 후속 Phase에서 이 문서와 상충하는 결정이 필요하면, 이 문서를 갱신하고 `docs/decisions/`에 ADR을 남긴다.

---

## 1. 한 줄 정의

**광일의 글쓰기 루틴에 정확히 맞는 기록 도구.**
입력 노동을 없애고, 그 시간을 묵상과 글쓰기 자체에 돌려준다.

이 프로젝트는 "블로그 플랫폼을 만드는 것"이 아니다.
이미 검증된 개인 루틴(요일별 묵상 + 기술 글, 2년간 1,000개+ 포스팅)을
범용 플랫폼의 마찰 없이 지속하게 하는 **1인 전용 도구**를 만드는 것이다.
광일의 루틴에 과적합(overfit)하는 것이 결함이 아니라 정체성이다.

---

## 2. 배경

### 2.1 현재 상태

- 티스토리에서 **기술 블로그**와 **묵상 블로그** 2개 운영 중
- 묵상 블로그의 고정 루틴:
  - **말씀 묵상(QT)**: 월~토. 「날마다 솟는 샘물」(365qt.com)의 '오늘의 큐티' 본문·질문(1/2/3/4/5-1/5-2) 기반. 로그인 필요 사이트
  - **설교 묵상**: 일요일. 당일 말씀 + 설교 제목 + 본문 + Summary
  - **찬양 묵상**: 매일. YouTube 임베드 + 섹션별 가사(Intro/Verse/Pre-Chorus/Chorus/Bridge/Interlude/Outro) + 기도문
- 이전 이력: **velog(2년) → 티스토리(2025.02~)** 이주 경험
  - 이주 회고: https://pangil-log.tistory.com/55
- 티스토리 실적: 일 20~30 조회, 1년 8개월 누적 방문 약 18,000

### 2.2 문제 정의의 층위

| 층위 | 내용 | 비중 |
|------|------|------|
| 표면 문제 | 티스토리 작성 시 서식 선택 depth 1회 추가 | 마이너 |
| 실질 비용 | 365qt 본문·질문을 매일 **수동 타이핑**하는 시간. 묵상이 아닌 '입력 노동'에 시간 소모 | **핵심** |
| 신뢰 문제 | 티스토리 방문자 통계가 부정확하다고 느낌 → 동기 시스템으로서 기능 저하 | 중간 |
| 정체성 욕구 | "나만의 블로그를 소유한 개발자"가 되고 싶음 | **감정적 엔진** |

### 2.3 Root Problem

> 고도로 구조화된 개인 글쓰기 루틴이 이미 존재하는데,
> 범용 플랫폼은 이 루틴을 지원하지 못해 매일 반복되는 입력 노동과 마찰이 누적된다.
> 동시에 통계의 부정확함이 동기 시스템을 약화시키고 있으며,
> 도구를 직접 소유하고 싶다는 개발자 정체성이 이주를 요구하고 있다.

## 3. 인터뷰 핵심 발견 (Phase 1-1)

### 3.1 글쓰기 습관은 검증 완료

- 2년간 1,000개 이상 포스팅. **리스크는 "글을 안 쓰게 되는 것"이 아니라 "도구를 안 쓰게 되는 것"**

### 3.2 프로젝트 생존 조건 (과거 프로젝트 부검)

- 꾸준히 쓴 프로젝트: 매일 신경 쓰는 것 + **UI가 마음에 들어 애착이 생긴 것**
- 방치된 프로젝트: 기획·디자인 없이 **바이브코딩으로 만든 것** → 애착 부재 → 유지보수 의욕 상실
- 결론: **만들기·쓰기·유지보수 모두 재밌고 애착이 가야 한다.** 기획/디자인 단계에 충분히 투자하는 것 자체가 첫 번째 생존 장치

### 3.3 velog → 티스토리 이주 이유 = 새 블로그의 필수 요구사항

| # | 이주 이유 | 새 블로그 반영 |
|---|----------|---------------|
| 1 | 통계·그래프가 꾸준함의 동기부여(보상 시스템)였음 | 통계 시스템 필요. 티스토리보다 정확하게 |
| 2 | 검색엔진 유입 + 유입 경로 분석 | SEO 인프라 + 유입 경로 추적 |
| 3 | 서식(템플릿)으로 통일된 포맷 + 스타일이 그대로 보이는 에디터 | 타입별 구조화 에디터 (핵심 설계) |

### 3.4 설계 제약: 좌우 분할 마크다운 에디터 금지

- velog 이탈 원인 중 하나가 **좌우 분할 마크다운 에디터** (작성 행위에 집중이 뺏겨 전달할 핵심에 집중 못함)
- **결정: 기술 글 에디터는 고정 툴바 WYSIWYG** (쓰는 자리에서 스타일이 바로 보이되, 좌우 분할·소스/미리보기 분리 금지. Tiptap 계열 검토). 상세·기각 대안은 `docs/decisions/001-editor-toolbar-model.md`(ADR-001) — 초기 "Notion식" 표현을 티스토리식 고정 툴바로 확정함
- 저장 포맷은 별개 논의 (Phase 5에서 결정: 에디터 UX ≠ 저장 포맷)

### 3.5 이주 전략

- **완전 이주** 확정. 티스토리 병행 운영 없음 (매일 이중 작업 = 지속 불가)
- 기존 글 마이그레이션: 작성일·제목·본문·해시태그·썸네일 이관, **원본 작성일 보존**
- 개발 기간 동안은 티스토리 루틴 유지 → 개발 완료 → 이주 → 90일 판정 (루틴 공백 없음)

## 4. 성공 기준 (Phase 1-2)

### 4.0 핵심 철학

성공은 "블로그가 잘 되는 것"이 아니라 **"도구가 루틴에 녹아드는 것"**이다.
작성 경험 지표 > 지속성 지표 > 독자 지표 순으로 우선한다.

### 4.1 정량 지표

**① 작성 마찰 지표 (존재 이유)**

| 지표 | 현재 (티스토리) | 목표 |
|------|----------------|------|
| QT 작성 시작 | 진입 → 글쓰기 → 서식 선택 → 본문·질문 수동 타이핑 | 진입 → **오늘의 초안 탭 1회** (본문·질문 채워짐) |
| QT 1편의 입력 노동 | 본문+질문 타이핑 수분 | **0분** |
| 찬양 묵상 세팅 | URL 임베드 + 제목·섹션 수동 | URL 1회 붙여넣기 → 임베드 + `아티스트 - 곡명` 제목 자동 제안 |

**② 지속성 지표**

- **공식 성공 판정: 이주 후 90일 시점에 티스토리로 회귀하지 않음**
  - 따라서 MVP 정의 = "티스토리 없이 90일 버틸 수 있는 최소 기능"
- 주간 작성 완주율: 기존 티스토리 루틴 수준 유지
- 크롤러 가동률: 월 실패 2회 이하, 실패 당일 인지(Slack 알림)

**③ 독자 지표 (후행, 조급해하지 않음)**

- 6개월 내 일 10~15 조회 (티스토리 시절 50% 회복)
- 12개월 내 일 20~30 조회 (완전 회복) — 스트레치 골
- 통계 데이터를 스스로 신뢰할 수 있는 상태

### 4.2 정성 기준

- 묵상할 때 타이핑이 아니라 묵상에 집중하게 됐다고 느낌
- 블로그 UI를 누군가에게 자랑하고 싶어짐 (애착의 신호)
- 기능 개선이 "부채감"이 아니라 "재미"로 느껴짐
- 포트폴리오/이력서에 이 프로젝트를 쓰게 됨

## 5. Non-goals (Phase 1-2)

### 5.1 영구 Non-goals (제품 정체성에 어긋남)

1. **멀티유저/회원 시스템** — 광일 1인의 도구. 타인 가입·권한 관리 없음 (본인 확정)
2. **범용 블로그 플랫폼화** — "남도 쓸 수 있게" 일반화하지 않음
3. **네이티브 앱** — 모바일은 반응형 웹으로 해결
4. **에디터의 무한 자유도** — 노션 수준의 블록 에디터를 만들지 않음. "블로그 글에 필요한 블록"까지만
5. **댓글 외부 위젯(giscus 등) 의존** — 댓글은 자체 구현으로 방향 확정 (아래 5.2 참고)

### 5.2 지금 안 함 (Backlog, MVP 이후)

| 우선순위 | 항목 | 비고 |
|---------|------|------|
| **1** | **자체 댓글 (승인제)** | 90일 생존 후 1순위. 설계 방향 확정: 관리자 승인 후 노출, 익명(닉네임+비밀번호), honeypot + rate limit, 새 댓글 Slack 알림. 티스토리 이탈에 댓글은 필수 조건이 아니므로 MVP 제외 |
| 2 | 통계 대시보드 UI | **수집은 Day 1부터**, 그래프는 나중 |
| 3 | 주간/월간 묵상 자동 회고, 스트릭 | 게이미피케이션 |
| 4 | 전문 검색(full-text) | 초기엔 태그/목록으로 충분 |
| 5 | 뉴스레터/구독 알림 | |
| 6 | 다크모드 외 테마 커스터마이징 | |

## 6. 대안 분석 (Phase 1-3)

### 6.1 전제가 되는 사실

**티스토리 Open API는 2024년 2월부로 완전 종료** (글 작성·수정 API 불가).
→ "티스토리에 남되 자동화만 얹기"라는 최선의 반론이 원천적으로 불가능.

### 6.2 대안 비교 요약

요구사항: ①365qt 초안 자동 생성 ②타입별 구조화 에디터 ③고정 툴바 WYSIWYG(좌우 분할 금지, ADR-001) ④정확한 통계 ⑤소유·정체성 ⑥자체 댓글

| 대안 | 결정적 결격 사유 |
|------|-----------------|
| 티스토리 잔류 | ①불가(API 종료), ②서식 depth 그대로, ④부정확(이탈 원인), ⑤불충족 |
| Ghost (셀프호스팅) | ②범용 에디터로 타입별 구조화 불가, 서버 관리 비용 |
| Obsidian Publish | ③마크다운 = velog 이탈 원인 재현, ①④⑥ 불가 |
| Notion + super.so | ④통계 불가, ⑤소유 아님, ⑥불가 |
| Headless CMS + 직접 FE | 가장 근접하나 어차피 FE 직접 개발 필요. CMS 스튜디오 커스텀 학습 비용 ≈ 자체 에디터 개발 비용이면서 외부 의존성만 추가 |
| **풀 직접 개발** | 아래 6.3의 약점 3개 외 전 항목 충족 |

### 6.3 직접 개발이 지는 지점 (인지하고 시작)

| 약점 | 대응 |
|------|------|
| 유지보수 완패 (티스토리는 절대 안 고장남) | 크롤러 실패 알림, 의존성 최소화, 무료 티어 구성으로 운영 비용 0원 유지 |
| SEO 제로 리셋 (301 리다이렉트도 불가) | sitemap·구조화 데이터·서치콘솔(Google/Naver) 등록을 MVP에 포함. 검색 유입 주력은 기술/커리어 글이므로 SEO 투자를 기술 글에 집중 |
| 초기 개발 투자 (수 주) | 개발 기간 중 티스토리 루틴 유지로 공백 제로 |

### 6.4 결론

> 직접 개발은 "블로그 플랫폼"으로서는 모든 대안에 지지만,
> "광일의 루틴 전용 도구"로서는 대체재가 없다.
> ①+②("로그인 사이트를 매일 크롤링해 구조화 초안을 만들어주는 블로그")는
> 시장에 존재하지 않는 카테고리이며, 유일한 경쟁 경로(티스토리 API)는 종료됐다.
> **결정: 직접 개발한다.** (2026-08-18, 이의 없음 확인)

## 7. 확정 요구사항 (Phase 1 종합)

1. **묵상 초안 자동 생성** — 365qt 크롤링으로 당일 본문·질문이 채워진 DRAFT 자동 생성. **최대 가치이자 단일 장애점** (실패 알림 필수)
2. **타입별 구조화 에디터** — 서식이 폼에 내장, 선택 depth 제로. 타입: QT / 설교 / 찬양 / 기술
3. **기술 에디터 = 고정 툴바 WYSIWYG** — 쓰는 자리 즉시 적용, 좌우 분할 마크다운 레이아웃 금지 (ADR-001)
4. **찬양 글 제목 자동 제안** — YouTube URL → oEmbed(title, author_name) → 정규화 휴리스틱(대괄호·구분자 처리) + 아티스트 사전(alias)으로 `아티스트 - 곡명` 자동 입력, 편집 가능. 파싱 실패 시 원본 제목 폴백
5. **통계 시스템** — 방문자 수, 체류 시간, 유입 경로. 대시보드 UI는 Backlog, **수집은 Day 1부터**
6. **완전 이주 + 마이그레이션** — 티스토리 백업 이관, 원본 작성일 보존
7. **SEO 인프라 MVP 포함** — sitemap, 구조화 데이터, OG, 서치콘솔 등록
8. **기획·디자인 선행** — 애착이 곧 유지보수 동력. 바이브코딩 금지

## 부록 A. 인터뷰 로그 요약 (Phase 1-1, 5문답)

1. **미룬 날의 걸림돌** → 서식보다 365qt 본문·질문 수동 타이핑이 실질 비용. + "요즘 시대에 걸맞는 개발자"라는 정체성 동기
2. **꾸준히 쓴 것 vs 방치된 것** → 매일 쓰는 것 + UI 애착 = 생존 / 바이브코딩 = 방치. 1,000개+ 포스팅으로 글쓰기 습관 검증
3. **이주 전략** → 완전 이주, 원본 작성일 보존. velog → 티스토리 이주 경험으로 심리적 저항 없음
4. **velog 이탈 이유** → 회고 글 분석: 통계(동기부여), 검색 유입, 서식 + 좌우 분할 마크다운의 아쉬움
5. **통계·에디터 확인** → 통계는 체류 시간까지 확장 희망, 기획 단계부터 설계. 에디터는 WYSIWYG 확정 (당시 "Notion식"으로 표현 → 이후 ADR-001에서 티스토리식 고정 툴바로 구체화)

## 부록 B. Phase 1-2 논쟁 포인트 결정 로그

1. "90일 미회귀 = 공식 성공 판정" → **동의** ("그 기간 지나면 무조건 내 블로그만 쓸 듯")
2. 댓글 → **자체 구현 선택** (승인제 최소 설계로 스팸 부채 통제, MVP 제외·Backlog 1순위)

4. 멀티유저 → **영구 Non-goal 확정** ("나 1인의 도구일 뿐")
